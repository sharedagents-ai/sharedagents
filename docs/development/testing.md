# Testing and verification

Install the development dependencies using [setup](setup.md). The default
suite is designed to run without production accounts or model calls.

## Default checks

```bash
python -m pytest -q -n auto -m "not e2e and not docker and not browser"
ruff check src tests scripts
ruff format --check src tests scripts
python -m pytest -q tests/test_no_local_references.py
python scripts/check_forbidden_patterns.py src docs scripts examples
mkdocs build --strict
```

Use a smaller worker count, such as `-n 4`, on a shared machine. Set
`PYTHONDONTWRITEBYTECODE=1` for local check runs to keep generated bytecode
from embedding checkout paths in the scanned source tree. Existing caches
are local build output; publication checks run on a clean Git archive.

## Choose coverage by change

| Change | Useful verification |
| --- | --- |
| Runtime behavior | Focused regression test and default suite |
| Authentication or permissions | Rejection and success cases, including cross-user isolation |
| Browser behavior | Relevant browser test and a small-screen/manual check where applicable |
| Provider/engine adapter | Contract tests with sanitized fixtures; explicit live check if needed |
| Packaging/assets | Build wheel and sdist, inspect contents, install into a fresh environment |
| Documentation | Strict MkDocs build, relative-link check, commands checked against CLI help |

## Optional checks

`e2e`, `docker`, and `browser` tests need their associated runtime or tooling.
Browser tests require Playwright and a compatible browser. Some modules use
`pytest.importorskip` when an optional dependency is unavailable. Report skips;
they are not evidence that the optional behavior passed.

The live model test is opt-in because it uses provider tokens. Configure
`SHAREDAGENTS_E2E_URL`, `SHAREDAGENTS_E2E_EMAIL`,
`SHAREDAGENTS_E2E_PASSWORD_FILE`, and `SHAREDAGENTS_E2E_MODELS` as documented
in `tests/test_e2e_live_model_reply.py`. Keep the password file private and
never commit live credentials or captured conversation data.

## Publication checks

Maintainers also scan the complete exported tree and both distributions against
their local credential values and private identity denylist. Generic checks
alone cannot know a deployment's secret values or host names. A successful scan
is a check of the exported snapshot, not a guarantee that a private repository's
old Git history is safe to publish.

The public repository must not receive private refs, commit objects, audit
logs, or deployment data. Follow the [release process](../../RELEASES.md) and
the [maintainer guide](maintaining.md).
